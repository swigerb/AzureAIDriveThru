## 2026-09-28 -- #128: reject menu key and alias collisions at load

- Root cause: `menu_utils._menu_key()`'s modifier-stripping (lowercase, strip every `(...)` group, strip trademark symbols, normalize the curly apostrophe -- intentional, "Tots"/"Tots (Extra Crispy)" must classify identically) can silently collapse two genuinely different items into the same lookup key, e.g. a draft pack's five differently-priced "(N piece)" nugget-size items. `_load_menu_data` built its `item_fields`/`alias_map` dicts by plain assignment, so a later item (or alias) silently overwrote an earlier one with no error -- last-write-wins, not fail-fast.
- **Two-pass algorithm, one implementation per language**: `menu_utils.validate_menu_key_collisions` (Python) / `MenuKeyValidator.ValidateNoCollisions` (C#, new file `MenuKeyValidator.cs` since no menu-normalization module existed in C# before this issue). Pass 1 builds every item's own key first (raising on an item-key/item-key collision); pass 2 then checks every alias against the now-complete key map plus a second alias-owner map (raising on alias-vs-item-key or alias-vs-alias collision), so an alias declared on an *earlier* item that collides with a *later* item's own key is still caught regardless of file order. An item's own alias matching its own key is explicitly not a collision (e.g. "Tots" aliased to "tots (large)").
